## 2026-08-24 - Escaping Inline Script JSON & Public Redirection Validation
**Vulnerability:** Inline JavaScript tags generated for HTML meta/double-meta redirects previously used raw `JSON.stringify(dest)`. If a destination URL or custom referrer contained closing HTML tags like `</script>`, it could break out of the script block and trigger Reflected/Stored XSS. Additionally, `/clean-redirect` lacked URL protocol validation, allowing unvalidated protocols such as `javascript:` or `data:`.
**Learning:** `JSON.stringify` does not escape `<`, `>`, or `/` characters by default, making string embedding inside inline `<script>` tags unsafe when handling untrusted user input or user-configurable parameters.
**Prevention:** Always use a helper like `safeJsonStringify` that replaces `<` with `\u003c`, `>` with `\u003e`, and `/` with `\u002f` when interpolating JSON values into inline script blocks. Strictly validate public redirection targets using regex `^https?://` to prevent open redirects and script execution.
